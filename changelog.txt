PYPATCHER - CHANGELOG
=====================
Format: Version (Datum) - Aenderungen. Neueste oben.
Versionen: siehe manifest.txt Abschnitt 16.

0.0.3-pre1 (in Arbeit)
----------------------
  Umfang 0.0.3: TypeScript/JSX (R016), Java (R032), Visual Basic
  (VB.NET und VBA/VB6, R033), Lua (R034), JSON mit Kommentaren (R024),
  Antworten aus einer Datei (--answers, R020).

  TypeScript, TSX, JSX (R016):
  - mode ts (*.ts, *.mts, *.cts), tsx (*.tsx), jsx (*.jsx) auf Basis des
    JS-Tokenizers; JSX-Elemente als Token mit exaktem Text.
  - Einheiten zusaetzlich: interface, enum, type-Alias, namespace/module;
    Methoden mit Modifikatoren, Generics, Rueckgabetypen, Dekoratoren.

  Java (R032):
  - mode java (*.java), Normalform java/1 (Tokens; Text-Bloecke exakt).
  - Einheiten: Klassen, Interfaces, Enums, Records, Annotationstypen,
    Methoden, Konstruktoren, innere Klassen ("Store.Entry.size");
    Ueberladungen name#1, name#2; Annotationen und Javadoc gehoeren dazu.

  Lua (R034):
  - mode lua (*.lua), Normalform lua/1; lange Zeichenketten/Kommentare
    ([[ ]], [==[ ]==]); Syntaxpruefung ueber Klammern und Bloecke.
  - Einheiten: function M.name / M:methode, local function, name =
    function, Tabellen mit Funktionsfeldern ("handlers.click"), innere
    Funktionen; Trennzeichen zwischen Tabellenfeldern werden gerichtet.

  Visual Basic (R033):
  - mode vb (*.vb, VB.NET) und vba (*.bas, *.cls, *.frm, *.vbs: VBA,
    VB6, VBScript); Normalform aus logischen Zeilen (" _" und ":"
    aufgeloest), ohne Gross-/Kleinschreibung, Kommentare ' und REM egal.
  - Einheiten: Sub, Function, Property, Operator, Custom Event, Class,
    Module, Structure, Interface, Namespace, Enum, Type; Kopf von
    VBA-/VB6-Exporten als @header; Suche notfalls ohne Gross-/Klein-
    schreibung. Declare/Delegate/Auto-Properties sind keine Einheiten.

  JSON mit Kommentaren (R024):
  - mode jsonc (*.jsonc, tsconfig*.json, .vscode/*.json ...): Kommentare
    und Komma am Ende erlaubt; Kommentare ueber einem Eintrag gehoeren
    zur Einheit. JSON5 bleibt offen.

  Antworten aus einer Datei (R020):
  - check/apply/run --answers DATEI (NAME=WERT je Zeile oder JSON).

  Aus dem fuenften Praxistest (ROM-Patcher, Patches 021-027):
  - Behoben: Suchbloecke (TEXT/TINS/TDEL) mit Leerzeichen-Einrueckung
    wurden nie gefunden ("Inhalt gleich, Einrueckung weicht ab"), obwohl
    dieselbe Schreibweise in Einfuegebloecken funktionierte. Leerzeichen
    in Vielfachen der Ebenen-Einheit zaehlen jetzt ueberall wie Tabs.
  - MOVE/COPY mit Leerzeichen im Pfad: Meldung nennt die Loesung ("...").
  - Hinweis, wenn ein Patch Dateien aendert, die pypatcher ohnehin
    ignoriert (im Test: ein Patch, der 19 .DS_Store-Dateien loescht).

  Sicherheit (Hinweis aus dem sechsten Praxistest, im Test bestaetigt):
  - Behoben: Ein Patch konnte in .git/ schreiben (z.B. .git/hooks/
    pre-commit - wird von Git ausgefuehrt). .git/, .hg/, .svn/ sind jetzt
    wie .patcher/ gesperrt.
  - Behoben: Ueber einen symbolischen Link auf ein Verzeichnis konnte ein
    Patch ausserhalb des Projekts schreiben. Pfade ueber symbolische Links
    werden abgelehnt; Rollback entfernt keine Links mehr als Verzeichnis.
  - Neuer Befehl help [BEFEHL] (KIs und Nutzer versuchten "help").

  JSON-Ausgabe (R038):
  - --json bei init, status, verify, log, check, apply, run, rollback,
    recover: genau ein JSON-Objekt (Format pypatcher-result/1) mit
    Ergebnis-Code, betroffenen Dateien, Journal, Tests, Hinweisen.
  - Konflikte strukturiert: welche Aenderung, aehnlichste Stelle mit
    Zeilen und Text, aehnliche/vorhandene Einheiten.

  Verzeichnisse (R038):
  - DMOVE, DCOPY, DDEL fuer ganze Verzeichnisse; beim Versiegeln wird die
    Dateiliste mit Hashes eingetragen - zusaetzliche, fehlende oder
    veraenderte Dateien brechen ab. Symbolische Links und .git darin
    werden abgelehnt; Rollback exakt.
  - Leer gewordene Verzeichnisse werden entfernt (Rollback legt sie an).

0.0.2 (2026-10-31) - Freigabe
-----------------------------
  Umfang 0.0.2 (Ergebnis von vier Praxistests mit einer anderen KI an
  einem echten Projekt - zuletzt mit Prompt und Entwuerfen im Chat):
  Korrekturen bei Ignore-Regeln, ein Befehl je Patch (run --test),
  Konfliktanzeige (R006), Python-Konstanten/Imports als Einheiten (R005),
  verschachtelte JS-Funktionen und Objekt-Methoden (R017), Startablauf
  im KI-Prompt.

  Ignore-Regeln:
  - .patcherignore wird nie verwaltet (gehoert zur Umgebung).
  - Neue Vorgaben: .DS_Store, Thumbs.db, desktop.ini (verify meldete
    unter macOS sonst Aenderungen) und *.ppatch (ein heruntergeladener
    Patch im Projekt war "neue Datei ausserhalb von Patches").
    "!muster" in .patcherignore nimmt eine Vorgabe zurueck.
  - Geaenderte Ignore-Regeln wirken sofort: neu ignorierte Dateien
    fallen aus der Verwaltung, statt ein neues Journal zu erzwingen.
  - init --force legt das Journal neu an (nur ohne angewendete Patches);
    vorher musste .patcher/ von Hand verschoben werden.

  Ein Befehl je Patch (apply/run):
  - --test BEFEHL bzw. "test" in .patcher/config.json: nach dem Anwenden
    Journal pruefen und Tests ausfuehren; --no-test schaltet ab.
  - Ergebniszeile, auch mit -q: "OK <id> | n Dateien | Journal OK |
    Tests OK". Statt check, apply, Tests, verify, status einzeln.
  - Exit-Code 6 bei fehlgeschlagenen Tests; --rollback-on-failure nimmt
    den Patch dann zurueck, sonst bleibt er zur Untersuchung angewendet.
    (Exit-Code fuer doctor, spaeter, wird 7.)

  Konfliktanzeige (R006):
  - Suchblock nicht gefunden: aehnlichste Stelle als kurzer Diff
    (- Patch, + Datei) bzw. "Inhalt gleich, Einrueckung weicht ab".
  - Einheit nicht gefunden: aehnliche bzw. vorhandene Einheiten.

  Python (R005):
  - Neue Einheiten: @imports (Import-Block am Modulanfang) und
    Zuweisungen mit einem Namen auf oberster Ebene und in Klassen
    ("LIMIT", "Config.port", auch dataclass-Felder "name: str").
  - UCOPY as= benennt auch Zuweisungen um; zwischen Zuweisungen wird ohne
    Leerzeilen eingefuegt.
  - create nutzt die neuen Einheiten (z.B. UNIT @imports statt
    Textblock).

  JavaScript (R017):
  - Funktionen in Funktionen und Methoden ("outer.inner",
    "Box.get.local").
  - Objekte in const/let/var mit Methoden und verschachtelten Objekten
    ("api.load", "api.sub.ping"); start-of:/end-of: auch fuer Objekte.
  - Kommas zwischen Objekt-Eintraegen werden beim Einfuegen, Ersetzen und
    Kopieren gerichtet; UCOPY as= benennt auch "name: function" um.

  Behoben (Fehlerbericht aus dem zweiten Praxistest):
  - Eine Python-Datei mit Syntaxfehler (ips.py) liess sich nicht
    ersetzen: create, seal und run scheiterten schon am Hash des
    Ausgangsstands, auch mit --level file und --compare text. Jetzt wird
    eine ungueltige Ausgangsdatei ohne vorgegebenes Profil als text
    behandelt (wie bei init) - mit Hinweis; der Ausgangsstand bleibt
    per Hash gesichert.
  - create --compare veraenderte nur die Art des Vergleichs, nicht das
    Profil im Patch; jetzt steht es als DEFAULT im Patch.

  Aus dem dritten Praxistest:
  - Neue, nicht verwaltete Dateien (z.B. heruntergeladene ZIPs im
    Projektordner) sind bei verify und nach run/apply nur ein Hinweis:
    "OK <id> | ... | Journal OK (2 unverwaltete Dateien)". Vorher meldete
    run FEHLER mit Exit-Code 3, obwohl der Patch korrekt war.
  - create mit Dateien statt Verzeichnissen erklaert, was zu tun ist.
  - README.md verweist KIs, die das Repository lesen, auf ki-prompt.txt
    (im Test lieferte eine KI ganze Dateien plus Erzeugungsskript statt
    eines Patches, weil sie den Prompt nicht kannte).

  Farben (R030, Vorschlag aus dem Praxistest):
  - gruen = Erfolg, rot = Fehler/Abbruch, gelb = Warnung, cyan = Hinweis;
    in Konfliktmeldungen "- Patch" rot und "+ Datei" gruen.
  - Nur am Terminal; --color auto|always|never, NO_COLOR, TERM=dumb.
    Ausgaben in Dateien/Pipes (Logs, KI) bleiben ohne Steuerzeichen.
  - Konfliktanzeige vergleicht jetzt zeichenweise: auch eine einzelne,
    leicht abweichende Zeile ("return 2" statt "return 1") wird gezeigt.

  Aus dem vierten Praxistest (KI mit Prompt, Entwuerfe im Chat):
  - UADD/UNIT duerfen mehrere ganze Einheiten in einem Block enthalten
    (die KI fuegte drei neue Funktionen mit einem UADD ein: "der neue
    Block ist keine einzelne Einheit"). Geprueft ueber die Hashes aller
    Einheiten; loser Code bleibt verboten (klarere Meldung).
  - "UNIT nur innerhalb eines FILE-Befehls" nennt die Zeile und wie man
    es korrigiert.
  - "rollback_on_failure": true in .patcher/config.json.
  - ki-prompt.txt: FILE-Pflicht, mehrere Einheiten je Block, REQ,
    automatisches Zuruecknehmen.

  KI-Prompt und Beispiele:
  - Startablauf fuer KIs mit Code-Ausfuehrung: Projekt und patcher.pyz
    einmal anfordern, Hilfe selbst mit -h nachsehen (im Praxistest fragte
    die KI mehrfach nach Hilfe-Ausgaben), keine Optionen erfinden.
  - Je Patch genau ein Befehl fuer den Nutzer: run ... -y -q --test.
  - Konfliktmeldungen mit aehnlichster Stelle zur Korrektur nutzen.
  - Neue Einheiten (Imports, Zuweisungen, innere Funktionen, Objekt-
    Methoden) im Prompt und als Beispiel 7 in ki-beispiele.txt.

0.0.1 (2026-10-30) - erste Freigabe
-----------------------------------
  Patchformat pypatcher/1 (Befehlsliste + Datenbloecke):
  - Kompaktes Textformat statt JSON: eine Zeile je Befehl (FILE, UNIT,
    UADD, TEXT ...), Code unveraendert in gezaehlten Datenbloecken, kein
    Escaping. Derselbe Patch ist damit rund halb so gross.
  - Pruefstufen --verify min|std|full (nur Datei / zusaetzlich
    Funktionen / alles); Hashes gekuerzt (--hash-len, Standard 16);
    beim Anwenden wird geprueft, was der Patch enthaelt.
  - Kein alter Code mehr im Patch, ausser als Suchtext fuer
    Textaenderungen; Kopien/Verschiebungen holen den Inhalt aus der Quelle.
  - Optionale Pakete (--max-size): Teilung nach Zeichenzahl, Paket- und
    Gesamt-Hash, Laden aus einem beliebigen Paket.
  - Entwuerfe im selben Format, Bloecke "@N ." ... "@." von Hand
    schreibbar; Beispiel examples/entwurf-beispiel.ppatch.
  - show stellt Einrueckungs-Ebenen wie in der Datei dar (--indent).

  Befehl create:
  - Patch aus zwei Staenden (ALT -> NEU): Einheiten-Vergleich fuer Python
    (UNIT/UADD/UDEL, Abstieg in Klassen), dateiuebergreifende UMOVE-Paare
    und UCOPY, Datei-MOVE/COPY, Rest als Textbloecke mit eindeutigem
    Kontext. Der Patch wird vor dem Speichern im Speicher angewendet und
    Byte fuer Byte mit NEU verglichen; nicht exakt Darstellbares wird als
    ganze Datei aufgenommen.

  Grundfunktionen:
  - Befehle init, status, verify, log, units, show, seal, create, check,
    apply, rollback, recover.
  - Patch-Befehle: Dateien ADD/DEL/REP/MOVE/COPY; Einheiten UNIT/UADD/
    UDEL/UCOPY/UMOVE (auch zwischen Dateien); Text TEXT/TINS/TDEL mit
    optionalem scope.
  - Vergleichsprofile raw/text/python; Normalform python/1 aus Syntaxbaum
    + Einrueckungs-Signatur; Hash auf Python 3.8, 3.11, 3.12 und 3.13
    identisch (f-String-Teile vereinheitlicht).
  - Relative Einrueckung im Patch, layout als Check, Ausweichform lit.
  - Journal mit Sicherung, atomarem Schreiben, exaktem Rollback (auch
    --to), recover nach Absturz; verify unterscheidet funktionale und
    kosmetische Abweichungen.
  - Neu angelegte Dateien erhalten die ueblichen Rechte (0666 - umask).
  - Beim Schreiben/Wiederherstellen einer .py-Datei wird ihr Bytecode in
    __pycache__ entfernt: Python erkennt veralteten Bytecode nur an
    Aenderungszeit (Sekunden) und Groesse - bei schnellem Patch/Rollback
    mit gleich langem Inhalt lief sonst alter Code (im Selbsttest
    aufgefallen).
  - Syntaxpruefung je Datei am Ende statt nach jeder Aenderung
    (Zwischenstaende von Textaenderungen duerfen ungueltig sein).
  - create waehlt die ganze Datei, wenn sie kleiner ist als die
    Einzelaenderungen.

  Web-Formate (Reihenfolge JS -> CSS -> HTML/XML):
  - mode js (*.js, *.mjs, *.cjs): eigener Tokenizer, Normalform js/1
    (Kommentare/Einrueckung egal, Zeichenketten/Templates/Regex exakt,
    Zeilenumbruch nur wo ASI-relevant); Einheiten Funktionen, Klassen,
    Methoden (inkl. #privat, get/set, Pfeilfunktionen in const/Feldern),
    JSDoc gehoert zur Einheit.
  - mode css (*.css) und scss (*.scss, *.less): Normalform css/1
    (Kommentare und unwichtiger Leerraum egal, Selektor-Leerraum und
    Reihenfolge zaehlen), Einheiten Regeln und At-Regeln inkl.
    Verschachtelung, Adresse ueber den Selektor ("@media (...)/.btn",
    ".btn{2}"). Adressen mit Leerzeichen stehen im Patch in "...".
  - mode html (*.html, *.htm, *.xhtml) und xml (*.xml, *.svg, *.xsd,
    *.xsl, *.xslt): Normalform html/1, xml/1 (Kommentare, Attribut-
    Reihenfolge, Anfuehrungszeichen, Entitaeten egal; Text-Leerraum zaehlt
    standardmaessig; <script>/<style> ueber JS-/CSS-Normalform);
    Einheiten Elemente mit robusten Adressen (#id, Tag + Klassen +
    Nummer, z.B. "html/body/main/div.card[2]").
  - Engine und create formatunabhaengig: Einheiten, Positionen,
    Abstaende und Umbenennen liefert der Adapter (adapters/base.py).

  Ablaufsteuerung und KI-Nutzung:
  - Steuerbefehle PRINT, INPUT (choices/default), IF/ELIF/ELSE/END,
    LABEL/GOTO, SET, EXIT; auch innerhalb eines FILE. Erst wird der
    Ablauf bestimmt, dann atomar angewendet; Antworten im Journal.
  - Neuer Befehl run: Entwurf direkt gegen das Zielprojekt pruefen und
    anwenden (Vorschau, Rueckfrage, Sicherung); --set fuer Antworten,
    -n Probelauf. check/apply ebenfalls mit --set.
  - Entwuerfe in Teilen ohne Hash ("1/?" ... "3/3"), mehrere Teile in
    einer Datei, Code-Zaeune und Chat-Text werden ignoriert.
  - seal mit Ablaufsteuerung prueft jeden moeglichen Ablauf.
  - ki-prompt.txt: Anleitung fuer KI-Assistenten (Beispiel wird getestet).

  Komprimierung, Erweiterbarkeit, KI mit Werkzeugen:
  - --compress (seal/create/pack): Datenbloecke gemeinsam mit zlib +
    Base64 in einem Sammelblock "@0 n z64"; Befehlsliste bleibt lesbar;
    an echten Patches 53-57 % weniger Zeichen.
  - USES: Patches nennen genutzte Funktionen (flow, z64); unbekannte
    Funktionen oder Block-Kodierungen -> klare Meldung statt Fehldeutung.
  - Neuer Befehl pack (umpacken/komprimieren/teilen, Hashes bleiben) und
    bundle (pypatcher als eine Datei patcher.pyz, ca. 70 KB).
  - ki-prompt.txt: Ablauf fuer KIs, die Code ausfuehren koennen (selbst
    pruefen, versiegeln, als Datei liefern) und Hinweise zum Sparen von
    Ausgabe.

  Weitere Sprachen und Datenformate:
  - mode c (*.c, *.h) und cpp (*.cpp, *.hpp ...): Normalform c/1
    (Kommentare/Leerraum egal, Zeichenketten und Praeprozessor zaehlen),
    Einheiten Funktionen, struct/union/enum, Klassen, Methoden, namespace
    ("app::Box::get"); Zugriffsangaben (public:) werden beachtet.
  - mode json (*.json ...): Normalform json/1 (Daten statt Formatierung,
    Schluesselreihenfolge optional), Einheiten ueber Pfade
    ("server/port"), Kommas werden beim Einfuegen/Loeschen gerichtet.
  - Adapter koennen nach Einheiten-Aenderungen Trennzeichen richten
    (repair, z.B. JSON-Kommas).

  KI-Beispiele und Freigabe:
  - ki-beispiele.txt: sechs getestete Auftraege mit Antworten (Python,
    JS/CSS mit Entscheidung, HTML, JSON, C, Antwort ueber zwei
    Nachrichten) zum Beispielprojekt examples/ki/projekt.
  - Behoben: lief ein Datenblock ueber zwei Chat-Nachrichten, wurde der
    schliessende Code-Zaun der ersten Nachricht Teil des Inhalts. Teile
    in Code-Zaeunen enden jetzt am schliessenden Zaun; Chat-Text und der
    oeffnende Zaun des naechsten Teils werden verworfen.
  - Behoben: Dateien, die selbst Patch-Kopfzeilen enthalten (z.B.
    ki-beispiele.txt), machten einen Patch unlesbar ("mehrere Patches in
    einer Datei"). Kopfzeilen mit fremder Kennung in Datenbloecken sind
    jetzt Inhalt. Pakete enden nie mit Leerzeilen oder Zaun-Zeilen (der
    Leser haette sie als Chat-Rest entfernt -> Paket-Hash falsch).
  - Versuchspatches (patch/) entfernt; sie bleiben in der Git-Historie.

  Entwicklung: alle Aenderungen ab der Vorabversion wurden mit pypatcher
  selbst als Patch erzeugt (create), angewendet und zurueckgenommen
  (Selbsttest).

Konzeptphase (ohne Version, 2026-10-30)
---------------------------------------
  Sechs Konzeptstufen (Details: manifest.txt Abschnitt 2, E1-E28):
  Hash-Konzept mit Normalformen (nur die Funktion zaehlt, Python-
  Einrueckung exakt), Vergleichsprofile je Datei, relative Einrueckung im
  Patch, Befehle fuer Dateien/Einheiten/Text inkl. copy/move, Journal mit
  exaktem Rollback, Versionierung ab 0.0.1, eigenes Repository.
  Das anfaengliche JSON-Patchformat wurde vor der Freigabe durch das
  kompakte Format pypatcher/1 ersetzt.
